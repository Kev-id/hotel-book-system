# 评价数据生成提示词 (v2.0 - AI增强版)

## 📋 使用说明

1. **前置准备**：先完成酒店列表生成（使用 `01-酒店列表生成提示词.md`）
2. **数据粘贴**：将生成的酒店JSON数据粘贴到下方指定位置
3. **复制提示词**：复制完整提示词到大语言模型
4. **分批生成**：由于数据量大且要求高，务必分批生成（建议每次5-10家酒店）
5. **保存数据**：将每批生成的JSON合并，保存为 `reviews.json`

# 评价数据格式（严格遵循）

```json
{
  "reviews": [
    {
      "hotelId": 整数（必须对应酒店列表中的id）,
      "userId": 整数（随机生成1-100之间，允许重复模拟复购）,
      "orderId": "字符串（格式：ORD + 随机8位数字）",
      "overallRating": 数字（1.0-5.0，保留一位小数）,
      "dimensions": {
        "cleanliness": 数字（1-5）,
        "service": 数字（1-5）,
        "location": 数字（1-5）,
        "facilities": 数字（1-5）,
        "value": 数字（1-5）
      },
      "content": "字符串（评价正文，80-500字）",
      "sentiment": "字符串（positive/neutral/negative）",
      "tags": ["数组", "包含3-5个关键词标签"],
      "userName": "字符串（用户昵称）",
      "userType": "字符串（business/family/couple/solo）",
      "checkInDate": "字符串（YYYY-MM-DD，过去6个月内）",
      "reviewDate": "字符串（YYYY-MM-DD，必须在checkInDate之后1-7天）",
      "roomType": "字符串（豪华大床房/行政套房等）",
      "stayNights": 整数（1-7）,
      "isSuspicious": 布尔值（默认false，异常评价设为true）
    }
  ]
}
```

# 核心生成规则

## 1. 评分与情感分布（每家酒店25条）

- **5星（10-12条）**: sentiment="positive"
- **4星（8-10条）**: sentiment="positive"
- **3星（3-4条）**: sentiment="neutral"
- **2星（1-2条）**: sentiment="negative"
- **1星（0-1条）**: sentiment="negative"

**平均评分**: 控制在 4.0-4.5 之间

## 2. 维度评分逻辑（Dimensions）

维度评分必须与总评（overallRating）强相关，但允许有细微差异以体现真实性：

- **高分场景**: 如果总评5星，所有维度应在4.5-5.0之间，至少有一个维度是5.0
- **低分场景**: 如果总评1-2星，至少有两个维度低于3.0
- **差异场景**: 例如"位置好但设施旧"，可以是 location=5.0, facilities=2.0, overall=3.5

## 3. 内容生成要求（关键！）

评价内容必须预埋关键词，以便AI系统提取洞察。

### A. 正面评价（5-4星）

必须包含具体亮点，从酒店的 `highlights` 字段中选取1-2个具体表扬。

**关键词库（正面）**：
- **服务**: "热情", "周到", "升级房型", "前台专业", "有求必应", "管家服务"
- **卫生**: "一尘不染", "干净卫生", "消毒仔细", "无异味", "整洁"
- **位置**: "地铁直达", "市中心", "交通便利", "风景好", "步行可达"
- **设施**: "泳池棒", "健身房新", "早餐丰富", "床品舒适", "WiFi快"

**示例**：
```
"这次入住体验非常棒！前台小姐姐很热情，帮我们升级房型到了江景房。房间在28楼，视野超级好，可以看到整个外滩夜景。特别推荐他们家的早餐丰富，现煮面条和新鲜果汁都很好吃。地铁直达，出行方便。床品很舒适，睡眠质量很好。"
```

### B. 负面评价（2-1星）

必须包含具体槽点，从酒店的 `potentialIssues` 字段中选取1-2个具体批评。

**关键词库（负面）**：
- **服务**: "态度差", "冷漠", "效率低", "爱答不理", "投诉无果"
- **卫生**: "有头发", "污渍", "潮湿", "异味", "蟑螂", "不干净"
- **位置**: "偏僻", "难找", "噪音大", "施工声", "交通不便"
- **设施**: "陈旧", "坏了", "网络差", "空调不冷", "隔音差", "电梯慢"

**示例**：
```
"非常失望！房间隔音差，隔壁说话听得一清二楚，晚上根本睡不好。卫生间有异味，发现有头发没清理干净。报修空调不冷，等了半天没人来。前台态度差，爱答不理的。这个价位真的不值，强烈不推荐。"
```

### C. 中评（3星）

优缺点参半，语气平淡客观。

**示例**：
```
"酒店位置还行，打车比较方便。房间大小一般，设施有点旧了。服务态度还可以，但效率不太高，退房排队等了挺久。早餐比较简单，选择不多。价格的话算是中规中矩吧，没有特别惊喜也没有特别失望。"
```

## 4. 异常/可疑评价注入（重要！用于测试AI质检）

在每25条评价中，必须包含 **1-2条**（约5-8%）`isSuspicious: true` 的评价，类型如下：

### 类型A：评分与内容矛盾
```json
{
  "overallRating": 5.0,
  "sentiment": "negative",
  "content": "体验非常差，房间很脏，服务也不好，隔音太差了，再也不来了。",
  "isSuspicious": true
}
```
**目的**: 测试AI能否识别评分与文本的不一致

### 类型B：内容过短/通用
```json
{
  "overallRating": 5.0,
  "content": "很好。",
  "isSuspicious": true
}
```
**目的**: 测试AI能否识别刷单嫌疑

### 类型C：广告/引流
```json
{
  "content": "...房间不错，加微信 xxxx 获取更低价格...",
  "isSuspicious": true
}
```
**目的**: 测试AI能否识别敏感词

## 5. 用户画像与行为特征

### business（商务旅客）
- **关注**: "WiFi快", "办公桌", "安静", "发票", "交通", "会议室"
- **时间**: 周一到周五入住
- **时长**: 1-3晚
- **语气**: 简洁、专业、注重效率

### family（家庭度假）
- **关注**: "儿童乐园", "泳池", "家庭房", "早餐", "安全", "亲子"
- **时间**: 周末或寒暑假
- **时长**: 3-7晚
- **语气**: 温馨，提到孩子

### couple（情侣出行）
- **关注**: "景观", "浪漫", "浴缸", "私密", "餐厅", "氛围"
- **时间**: 周末/纪念日
- **时长**: 2-3晚
- **语气**: 感性、浪漫

### solo（独行旅客）
- **关注**: "安全", "性价比", "便利", "社交", "简单"
- **时长**: 1-2晚
- **语气**: 客观、理性

## 6. 标签（Tags）生成

根据内容自动提取3-5个标签，必须包含：
- 1个维度标签（如: #服务周到, #位置优越）
- 1个设施标签（如: #早餐丰富, #泳池不错）
- 1个情感标签（如: #性价比高, #失望体验）

**示例**: `["#服务热情", "#干净卫生", "#WiFi快", "#性价比高", "#适合办公"]`

# 时间与逻辑约束

1. **日期逻辑**: `reviewDate` 必须晚于 `checkInDate`，且间隔在 1-7 天之间
2. **时间跨度**: `checkInDate` 均匀分布在 **过去6个月** 内
3. **房型匹配**: `roomType` 使用常见房型（豪华大床房、行政套房、总统套房等）
4. **用户复购**: 部分 `userId` 应该重复出现，模拟老用户在不同酒店的入住

## 💡 进阶使用技巧

### 1. 控制生成节奏

由于LLM的输出长度限制，一次性生成几百家酒店的评价是不现实的。

**策略**: 每次只给模型 **5-10家酒店** 的数据

**操作**:
- 第一次：粘贴酒店1-10的数据 + 提示词
- 得到结果后，回复："继续，生成酒店11-20的数据"
- 模型会保持上下文风格，继续生成

### 2. 验证数据质量（Python脚本辅助）

生成 `reviews.json` 后，建议运行一个简单的脚本检查关键指标：

```python
import json

with open('reviews.json', 'r', encoding='utf-8') as f:
    data = json.load(f)

reviews = data['reviews']
print(f"总评价数: {len(reviews)}")

# 检查异常评价比例
suspicious = [r for r in reviews if r.get('isSuspicious')]
print(f"可疑评价数: {len(suspicious)} ({len(suspicious)/len(reviews)*100:.2f}%)")

# 检查情感一致性
mismatch = [r for r in reviews if not r.get('isSuspicious') and
             ((r['overallRating'] >= 4.5 and r['sentiment'] != 'positive') or
              (r['overallRating'] <= 2.5 and r['sentiment'] != 'negative'))]
if mismatch:
    print(f"警告: 发现 {len(mismatch)} 条非异常但情感不一致的评价")
else:
    print("✅ 情感一致性检查通过")

# 检查关键词覆盖
all_content = " ".join([r['content'] for r in reviews])
keywords = ["隔音差", "早餐丰富", "服务热情", "有头发", "地铁直达"]
for kw in keywords:
    if kw in all_content:
        print(f"✅ 包含关键词: {kw}")
    else:
        print(f"❌ 缺失关键词: {kw}")

# 检查每家酒店的评价数量
from collections import Counter
hotel_counts = Counter([r['hotelId'] for r in reviews])
print(f"\n每家酒店评价数量:")
for hotel_id, count in sorted(hotel_counts.items()):
    status = "✅" if count == 25 else "❌"
    print(f"  {status} 酒店ID {hotel_id}: {count}条")
```

### 3. 处理"幻觉"

如果模型生成的房型不在酒店列表中：

**修正**: 在提示词的"酒店列表"部分，明确列出该酒店的房型

**后处理**: 编写脚本，将生成的房型名称统一为标准房型

## 🛠️ 数据合并脚本

生成多批数据后，使用以下脚本合并：

```javascript
// merge-reviews.js
const fs = require('fs');

const files = ['reviews-batch1.json', 'reviews-batch2.json', 'reviews-batch3.json', 'reviews-batch4.json', 'reviews-batch5.json', 'reviews-batch6.json'];
let allReviews = [];

files.forEach((file, index) => {
  try {
    const content = fs.readFileSync(file, 'utf-8');
    const cleanContent = content.replace(/```json/g, '').replace(/```/g, '').trim();
    const data = JSON.parse(cleanContent);
    const reviews = data.reviews || data; // 兼容不同格式
    
    allReviews = [...allReviews, ...reviews];
    console.log(`✅ ${file} 合并成功，当前总数：${allReviews.length}`);
  } catch (e) {
    console.error(`❌ ${file} 解析失败:`, e.message);
  }
});

fs.writeFileSync('reviews.json', JSON.stringify({ reviews: allReviews }, null, 2));
console.log(`🎉 完成！总共生成 ${allReviews.length} 条评价，已保存至 reviews.json`);
```
