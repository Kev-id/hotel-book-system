# AI数据生成模板使用指南

## 📋 概述

本目录包含用于生成酒店评价数据的AI提示词模板。你可以将这些模板复制到任何大语言模型（ChatGPT、Claude、通义千问等），让AI批量生成评价数据，然后将生成的JSON文件交给agent导入数据库。

## 🎯 优势

- ✅ 不消耗项目API的token
- ✅ 可以使用任何大语言模型
- ✅ 可以多次调整和重新生成
- ✅ 生成速度更快（一次性批量生成）
- ✅ 更容易审核和修改

## 📁 文件说明

```
AI数据生成模板/
├── README.md                          # 本文件
├── 01-酒店列表生成提示词.md            # 生成酒店基础信息
├── 02-评价数据生成提示词.md            # 生成评价文本
├── 03-数据格式说明.md                  # JSON格式规范
└── 示例输出/
    ├── hotels-example.json            # 酒店数据示例
    └── reviews-example.json           # 评价数据示例
```

## 🚀 使用流程

### 步骤1：生成酒店列表

1. 打开 `01-酒店列表生成提示词.md`
2. 复制提示词到大语言模型
3. 根据需要调整城市和数量
4. 获取生成的JSON数据
5. 保存为 `hotels.json`

### 步骤2：生成评价数据

1. 打开 `02-评价数据生成提示词.md`
2. 将步骤1生成的酒店信息粘贴到提示词中
3. 复制完整提示词到大语言模型
4. 获取生成的JSON数据
5. 保存为 `reviews.json`

### 步骤3：导入数据库

1. 将 `hotels.json` 和 `reviews.json` 放到项目目录
2. 告诉agent："我已经生成了酒店和评价数据，请帮我导入数据库"
3. Agent会自动处理导入和生成其他关联数据（订单、收藏、价格历史）

## 💡 使用技巧

### 技巧1：分批生成

如果需要生成大量数据（如60家酒店），建议分批生成：
- 第1批：上海15家
- 第2批：北京15家
- 第3批：深圳15家
- 第4批：其他城市15家

每批生成后保存，最后合并JSON文件。

### 技巧2：多样性控制

在提示词中可以要求：
- "每家酒店的评价风格要有差异"
- "包含不同类型的用户（商务、家庭、情侣等）"
- "评分分布要自然（偏向4-5星）"

### 技巧3：质量检查

生成后检查：
- JSON格式是否正确
- 评价内容是否自然
- 评分与内容是否一致
- 是否有重复内容

### 技巧4：迭代优化

如果第一次生成的质量不满意：
- 调整提示词中的要求
- 增加具体的示例
- 重新生成部分数据

## 📊 数据量建议

### 推荐配置（60家酒店）

```
城市分布：
- 上海：15家 × 25条评价 = 375条
- 北京：15家 × 25条评价 = 375条
- 深圳：15家 × 25条评价 = 375条
- 其他：15家 × 25条评价 = 375条

总计：60家酒店，1500条评价
```

### 生成时间估算

使用大语言模型批量生成：
- 酒店列表（60家）：5-10分钟
- 评价数据（1500条）：30-60分钟（分4批）

## ⚠️ 注意事项

1. **JSON格式**
   - 确保生成的是有效的JSON格式
   - 注意中文字符的转义
   - 检查括号和逗号是否正确

2. **数据一致性**
   - 酒店ID要唯一
   - 评价中的hotelId要对应酒店列表中的ID
   - 评分范围：1-5（可以有小数）

3. **内容质量**
   - 评价长度：80-500字
   - 避免过于模板化
   - 包含具体细节

4. **文件大小**
   - 单个JSON文件建议不超过5MB
   - 如果太大，分成多个文件

## 🔧 故障排除

### 问题1：JSON格式错误

**症状**：导入时报错"Invalid JSON"

**解决**：
1. 使用在线JSON验证工具检查
2. 检查是否有多余的逗号
3. 检查中文引号是否正确

### 问题2：生成的内容太相似

**症状**：评价内容重复或模板化

**解决**：
1. 在提示词中强调"多样性"
2. 提供更多具体的场景示例
3. 分批生成，每批使用不同的提示词变体

### 问题3：评分与内容不一致

**症状**：5星评价但内容是负面的

**解决**：
1. 在提示词中明确要求一致性
2. 生成后人工检查
3. 使用脚本自动检查并标记
