## 🏨 酒店数据格式（hotels.json）

### 完整格式

```json
{
  "hotels": [
    {
      "id": 1,
      "name": "上海外滩华尔道夫酒店",
      "city": "shanghai",
      "address": "上海市黄浦区中山东一路2号",
      "stars": 5,
      "basePrice": 2200,
      "tags": ["WiFi", "停车场", "健身房", "游泳池", "SPA"],
      "facilities": ["江景客房", "屋顶酒吧", "24小时管家服务"],
      "description": "坐落于外滩核心位置...",
      "type": "luxury"
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| id | 整数 | ✅ | 酒店唯一ID，从1开始递增 | 1, 2, 3... |
| name | 字符串 | ✅ | 酒店名称（中文） | "上海外滩华尔道夫酒店" |
| city | 字符串 | ✅ | 城市拼音（小写） | "shanghai", "beijing" |
| address | 字符串 | ✅ | 详细地址 | "上海市黄浦区中山东一路2号" |
| stars | 整数 | ✅ | 星级（2-5） | 5 |
| basePrice | 整数 | ✅ | 基础价格（元） | 2200 |
| tags | 数组 | ✅ | 设施标签 | ["WiFi", "停车场"] |
| facilities | 数组 | ✅ | 具体设施 | ["江景客房", "屋顶酒吧"] |
| description | 字符串 | ✅ | 酒店描述（100-200字） | "坐落于外滩..." |
| type | 字符串 | ✅ | 酒店类型 | "luxury", "business", "resort" |

### 城市代码

| 城市 | 代码 |
|------|------|
| 上海 | shanghai |
| 北京 | beijing |
| 深圳 | shenzhen |
| 广州 | guangzhou |
| 成都 | chengdu |
| 杭州 | hangzhou |
| 西安 | xian |
| 南京 | nanjing |
| 三亚 | sanya |

### 酒店类型

| 类型 | 说明 | 价格范围 |
|------|------|----------|
| luxury | 奢华型 | 1500-3000元 |
| business | 商务型 | 800-1500元 |
| resort | 度假型 | 1000-2000元 |

## 💬 评价数据格式（reviews.json）

### 完整格式

```json
{
  "reviews": [
    {
      "hotelId": 1,
      "rating": 4.5,
      "content": "这次入住体验非常棒！前台小姐姐很热情...",
      "userName": "旅行达人小明",
      "userType": "business",
      "checkInDate": "2025-12-15",
      "roomType": "豪华大床房",
      "stayNights": 2
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 | 示例 |
|------|------|------|------|------|
| hotelId | 整数 | ✅ | 对应酒店ID | 1 |
| rating | 浮点数 | ✅ | 评分（1.0-5.0） | 4.5 |
| content | 字符串 | ✅ | 评价内容（80-500字） | "这次入住体验..." |
| userName | 字符串 | ✅ | 用户昵称 | "旅行达人小明" |
| userType | 字符串 | ✅ | 用户类型 | "business" |
| checkInDate | 字符串 | ✅ | 入住日期（YYYY-MM-DD） | "2025-12-15" |
| roomType | 字符串 | ✅ | 房型 | "豪华大床房" |
| stayNights | 整数 | ✅ | 住宿晚数（1-7） | 2 |

### 用户类型

| 类型 | 说明 | 特征 |
|------|------|------|
| business | 商务旅客 | 关注效率、WiFi、位置 |
| family | 家庭度假 | 关注儿童设施、房间大小 |
| couple | 情侣出行 | 关注浪漫氛围、景观 |
| solo | 独自旅行 | 关注安全、性价比 |

### 评分与内容一致性

| 评分 | 情感 | 内容特征 |
|------|------|----------|
| 5.0 | 非常满意 | 全是优点，强烈推荐 |
| 4.0-4.9 | 满意 | 优点多，小瑕疵 |
| 3.0-3.9 | 一般 | 优缺点各半 |
| 2.0-2.9 | 不满意 | 缺点多，失望 |
| 1.0-1.9 | 非常不满意 | 严重问题，投诉 |

### 房型示例

- 豪华大床房
- 豪华双床房
- 行政套房
- 总统套房
- 江景房
- 海景房
- 园景房

## ✅ 数据验证规则

### 酒店数据验证

```javascript
验证规则：
1. id必须唯一且连续（1, 2, 3...）
2. city必须是有效的城市代码
3. stars必须是2-5之间的整数
4. basePrice必须是正整数
5. tags和facilities必须是非空数组
6. description长度必须在100-200字之间
7. type必须是 luxury/business/resort 之一
```

### 评价数据验证

```javascript
验证规则：
1. hotelId必须对应酒店列表中的ID
2. rating必须在1.0-5.0之间
3. content长度必须在80-500字之间
4. userType必须是 business/family/couple/solo 之一
5. checkInDate必须是有效的日期格式（YYYY-MM-DD）
6. checkInDate必须在过去6个月内
7. stayNights必须是1-7之间的整数
8. 评分与内容情感必须一致
```

## 🔧 常见问题

### Q1: JSON格式错误怎么办？

**A:** 使用在线JSON验证工具检查：
- https://jsonlint.com/
- https://www.json.cn/

常见错误：
- 多余的逗号
- 中文引号（应该用英文引号）
- 缺少括号或大括号

### Q2: 如何合并多个JSON文件？

**A:** 如果分批生成了多个文件，需要手工合并：

```json
{
  "reviews": [
    ...文件1的reviews数组内容...,
    ...文件2的reviews数组内容...,
    ...文件3的reviews数组内容...
  ]
}
```

注意：
- 只保留一个外层的 `{"reviews": [...]}`
- 合并时注意逗号

### Q3: 评价数量不对怎么办？

**A:** 检查每家酒店的评价数量：

```javascript
// 简单的检查脚本
const data = require('./reviews.json');
const countByHotel = {};

data.reviews.forEach(review => {
  countByHotel[review.hotelId] = (countByHotel[review.hotelId] || 0) + 1;
});

console.log(countByHotel);
// 应该每家酒店都是25条
```

### Q4: 日期格式不对怎么办？

**A:** 确保日期格式为 `YYYY-MM-DD`：
- ✅ 正确：`"2025-12-15"`
- ❌ 错误：`"2025/12/15"`
- ❌ 错误：`"12-15-2025"`
