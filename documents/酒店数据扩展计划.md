# 酒店数据扩展计划

## 📋 项目背景

当前系统只有4家精选酒店，数据量不足以充分展示AI功能（任务12/13/14）的效果。需要扩展到60-80家酒店，并确保数据质量能够支持AI功能演示。

## 🎯 核心目标

1. **扩展酒店数量**：从4家增加到60-80家
2. **保证数据质量**：每家酒店都有足够的评价、订单、收藏、价格历史数据
3. **支持AI功能**：确保任务12/13/14的AI功能能够有效展示
4. **中文化**：所有数据使用中文，符合国内用户习惯

## 🔍 关键决策

### 决策1：统一数据标准 vs 分层数据标准

**方案A：统一高质量标准（推荐）**
- 所有60-80家酒店使用相同的数据标准
- 每家酒店：20-30条评价、15-25个订单、3-8个收藏、90天价格历史
- 优点：实施简单、数据一致、AI效果更真实
- 缺点：生成成本较高（需要更多AI调用）

**方案B：分层数据标准**
- 精选展示酒店（30-35家）：高质量数据，用于AI功能演示
- 背景酒店（30-50家）：简化数据，用于丰富列表展示
- 优点：成本较低、重点突出
- 缺点：实施复杂、数据不一致

**当前倾向：方案A（待确认）**

### 决策2：数据来源

**方案A：AI辅助生成（推荐）**
- 使用通义千问API生成评价文本
- 使用规则生成订单、价格历史等结构化数据
- 优点：完全中文化、可控、与现有系统集成
- 缺点：需要设计好的prompt

**方案B：外部数据集**
- Kaggle等平台的酒店数据集
- 优点：数据真实
- 缺点：英文数据、不符合国内习惯、需要大量清洗

**方案C：爬虫采集**
- 从携程/美团等平台爬取
- 优点：数据最真实
- 缺点：法律风险、技术难度高、不推荐

**当前倾向：方案A（待确认）**

### 决策3：是否需要人工设计的特征

**原设计理念：**
- 人工注入关键词（每家酒店3-5个亮点和槽点）
- 人工注入异常模式（订单暴跌、评分跳水等）
- 基于用户画像精心设计订单和收藏

**新思路：**
- AI功能本质是模式识别，不需要过度设计
- 自然生成的数据反而更能体现AI价值
- 只要数据量足够、分布合理，AI就能工作

**当前倾向：不需要过度设计，让数据自然生成（待确认）**

## 🛠️ 技术实施方案

### 方案架构

```
数据生成流程：

1. 酒店基础信息生成
   ├─ 手工定义或AI生成酒店名称
   ├─ 基于真实地标生成地址
   ├─ 定义星级、价格、设施
   └─ 输出：hotels.json

2. 评价文本生成（AI辅助）
   ├─ 调用通义千问API
   ├─ 基于酒店特征生成评价
   ├─ 确保评分与内容一致
   └─ 输出：reviews.json

3. 订单数据生成（规则生成）
   ├─ 基于用户画像分配订单
   ├─ 生成合理的日期和价格
   ├─ 分配订单状态
   └─ 输出：orders.json

4. 收藏数据生成（规则生成）
   ├─ 基于用户画像分配收藏
   ├─ 生成分类和备注
   └─ 输出：favorites.json

5. 价格历史生成（规则生成）
   ├─ 生成90天价格记录
   ├─ 应用周末和节假日溢价
   └─ 输出：price_history.json

6. 数据导入数据库
   ├─ 清理现有数据
   ├─ 批量导入新数据
   └─ 验证数据完整性
```

### AI评价生成Prompt设计

```javascript
评价生成Prompt模板：

基础模板：
"请为以下酒店生成一条真实的用户评价：
酒店名称：{hotelName}
星级：{stars}星
主要设施：{facilities}
评分：{rating}星

要求：
1. 评价长度：{length}字左右
2. 评分与内容一致（{rating}星应该{sentiment}）
3. 包含具体细节（房间、服务、设施等）
4. 使用自然的中文表达
5. 不要过于夸张或模板化

请直接输出评价内容，不要包含其他说明。"

变体：
- 好评模板（4-5星）
- 中评模板（3星）
- 差评模板（1-2星）
- 商务旅客视角
- 家庭度假视角
- 情侣度假视角
```

## ⚠️ 风险和注意事项

### 风险1：AI生成质量不稳定
- **风险**：AI生成的评价可能质量参差不齐
- **缓解**：设计多个prompt模板，测试后选择最佳
- **备选**：手工审核并调整部分评价

### 风险2：数据量过大导致性能问题
- **风险**：80家酒店 × 25条评价 = 2000条评价，可能影响前端性能
- **缓解**：前端实现分页和虚拟滚动
- **备选**：减少酒店数量到60家

### 风险3：AI功能效果不如预期
- **风险**：自然生成的数据可能不如人工设计的数据展示效果好
- **缓解**：在测试阶段充分验证AI功能
- **备选**：为部分酒店添加人工设计的特征

### 风险4：时间成本超出预期
- **风险**：脚本开发和调试可能需要更多时间
- **缓解**：分阶段实施，先完成核心功能
- **备选**：先生成30-40家酒店，后续再扩展
